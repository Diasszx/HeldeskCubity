# MEMORIAL TÉCNICO DE DESENVOLVIMENTO — complemento de CD

**Projeto:** Cubity Support. **Data:** 05/10/2026. **Finalidade:** decisões da publicação gratuita para demonstração.

A documentação formal anterior está na branch de documentação e ainda não integra a `main` usada como base desta feature. Este complemento registra as novas decisões para incorporação na próxima revisão daquele documento, incluindo a publicação cloud confirmada nesta sessão.

| Decisão                                                       | Justificativa e alternativa                                                                                                                                               | Consequência                                                                                                                           |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Render Free para aplicação; Neon Free para banco              | Oferecem hospedagem Node e PostgreSQL com cotas gratuitas. Banco Free do Render expira em 30 dias; VPS exigiria operação própria e disponibilidade de recursos gratuitos. | Pausa por inatividade e cotas são aceitas para demonstração. Não há garantia de disponibilidade contínua.                              |
| React compilado servido por NestJS no mesmo domínio           | Reutiliza `/api`, sessões e CSRF sem introduzir cookies entre domínios. Frontend estático em outro provedor exigiria proxy ou alteração desse contrato.                   | Um único serviço hospeda as duas partes; Compose com Nginx permanece independente.                                                     |
| CD nativo aguardando checks da main                           | `autoDeployTrigger: checksPass` usa os checks existentes sem duplicar pipeline nem guardar token de deploy no GitHub.                                                     | Contas, integração GitHub e primeiro deploy exigem configuração do operador; a criação inicial não prova o gate dos deploys seguintes. |
| Migrations no comando de início cloud                         | Plano gratuito não oferece pre-deploy separado. Aplicação só inicia após sucesso, usando conexão direta TLS.                                                              | Reinícios reaplicam o histórico idempotente; migrations devem ser compatíveis com a versão anterior ainda em execução.                 |
| Modo Render explícito para TLS                                | Plataforma termina TLS e não expõe diretamente a porta HTTP. Confiar genericamente em qualquer `X-Forwarded-Proto` permitiria spoofing em outros ambientes.               | Variáveis oficiais são validadas; protocolo normalizado independe de cabeçalhos do cliente. Não usar o modo fora dessa topologia.      |
| Provisionamento explícito e idempotente com segredos privados | Seed local contém credencial pública e é recusado em produção. Não criar endpoint administrativo para contornar ausência de shell gratuito.                               | Comando local autorizado cria usuários/categorias por transação sem redefinir contas existentes.                                       |
| Sessões e negócio no PostgreSQL persistente                   | Reutiliza Prisma e connect-pg-simple; arquivos do Render são efêmeros e MemoryStore perderia sessões no reinício.                                                         | Preservar banco e SESSION_SECRET para conservar sessões; observar cotas e latência do Neon.                                            |
| Rollback de código separado da recuperação de dados           | Reverter versão não desfaz efeitos de migrations.                                                                                                                         | Exigir compatibilidade de schema e backup antes de mudanças destrutivas.                                                               |

Express 5.2.1 já era utilizado pelo adaptador NestJS e passa a ser dependência direta porque o middleware de arquivos estáticos o importa explicitamente. Não há mudança de contrato nos endpoints de negócio, modelo do banco ou permissões.

Comandos, variáveis, resultados e referências: [guia de CD](CD.md). A aplicação está publicada em [Cubity Support](https://cubity-support-demo.onrender.com/login); o painel confirma `main`, commit `90b1e19`, Live e primeiro deploy por Blueprint. O provisionamento Neon foi concluído e o responsável confirmou acesso.

Por decisão posterior do responsável, as credenciais de avaliação são públicas no README e no guia de CD. Conexões PostgreSQL e segredo de sessão permanecem privados. A senha informada para Ana tem 11 caracteres e diverge do mínimo de 12 exigido para criar contas novas; a documentação registra essa limitação sem modificar contas existentes.

[Evidências](screenshots/CD.md) distinguem publicação real de testes locais. Bloqueio remoto por falha de CI e persistência após reinício cloud ainda não foram demonstrados.
